# Inventário de dados

Estado: campos de Expense e Income **IMPLEMENTADOS no modelo, API e cliente iOS** e persistidos somente com valores sintéticos em PostgreSQL local/teste. O cliente mantém rascunho/resultado apenas em memória. Tratamento de dados pessoais ou financeiros reais permanece **PLANEJADO e inexistente**. Não há conta, usuário real, autenticação, fornecedor ou ambiente de produção.

As linhas abaixo distinguem o modelo, a validação técnica sintética e o futuro tratamento real. Os campos devolvidos pela API — exceto UserID, que não integra o contrato do cliente — existem transitoriamente na memória do app iOS; nenhum deles é gravado em storage local. Income não cria campos estruturados para salário, empregador, source, categoria, conta ou recorrência. A descrição continua livre e pode, por escolha do usuário, conter essas informações sensíveis; coletar ou incentivar esse conteúdo sem necessidade contrariaria minimização. Finalidade de produto, titular, base legal, retenção, compartilhamento, fornecedores, localização de produção e demais decisões permanecem a definir antes de qualquer usuário externo. Não usar dados reais como exemplo.
